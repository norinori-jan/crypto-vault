## 🎓 セキュリティ学習とは

crypto-vault は単なる「パスワード保管庫」ではなく、**セキュリティ教育プラットフォーム**です。

### なぜセキュリティを学ぶ必要があるのか？

- ✅ **自分のセキュリティ設定を理解できる** → より安全な選択ができる
- ✅ **暗号化技術への信頼が生まれる** → 安心して使用できる
- ✅ **脅威モデルを認識できる** → 自分を守る知識が増える
- ✅ **他のアプリ選択の際の参考になる** → リテラシー向上

### 2️⃣ **Security Coach** — リアルタイム指導

**目的**: パスワード入力時に「強度」「改善方法」を指導

```
パスワード入力中...

強度: ●●●●○ (94 / 100)

✨ 素晴らしい！
• 大文字・小文字・数字を含む
• 12文字以上の長さ
• 辞書にない組み合わせ

💡 なぜ強力なのか:
PBKDF2 で 200,000 回反復するため、
ブルートフォース攻撃に約 100 年かかる
```

#### 分析項目

| 項目 | 判定基準 |
|------|--------|
| **長さ** | 12文字以上推奨 |
| **大文字** | A-Z を含む |
| **小文字** | a-z を含む |
| **数字** | 0-9 を含む |
| **記号** | !@#$%^&* などを含む |
| **連続パターン** | aaa など連続なし |
| **辞書ワード** | password など一般語なし |
| **Have I Been Pwned** | 過去漏洩データに含まれていないか |

#### ブルートフォース推定時間の計算

```
推定時間 = (可能な文字種^長さ) / (GPU処理速度 × PBKDF2反復)

例:
• 12文字（大小英数+記号）: 約 100 年
• 8文字（大小英数のみ）: 約 1 秒
• 16文字（大小英数+記号）: 約 10,000 年
```

**重要**: PBKDF2 は 200,000 回反復することで、
GPU でも最新のハードウェアで 1 秒あたり ~100 パスワードしか試せません。

### 3️⃣ **Security Lab** — インタラクティブ実験

**目的**: 暗号化技術を「見て・触って」学ぶ

#### ⓵ PBKDF2 シミュレータ

```
【入力】
パスワード: my-secure-password
反復回数: 200,000

【計算開始】
↓ (計算中...)

【結果】
計算時間: 125 ms
Salt: 4f2a7c9e...
導出キー: a7f4b9d2... (SHA-256)
```

**学べること**:
- 反復回数を 10 倍にすると計算時間も ~10 倍
- 計算は遅いほど安全（ブルートフォースが遅くなる）
- Salt はパスワードごとにランダム生成

#### ⓶ AES-256-GCM 破損デモ

```
【暗号化】
平文: "This is secret data"
↓ (AES-256-GCM 暗号化)
暗号文: 7a3c4e9f... (GCM タグ付き)

【正常な復号化】
復号化: "This is secret data" ✅

【1バイト改変して復号化】
暗号文: 7a3d4e9f... (先頭1バイト改変)
↓ (復号化試行)
❌ エラー! GCM タグが不正を検知
```

**学べること**:
- GCM は認証付き暗号化
- 1 ビットの改変でも即座に検知
- サーバー側での改ざん攻撃は不可能

#### ⓷ HIBP k-Anonymity デモ

```
【あなたのパスワード】
my-secure-password

【SHA-1 ハッシュ】
完全: a4d87a...（SHA-1）

【Have I Been Pwned への送信】
送信部分: a4d87（先頭5文字のみ） ← サーバーへ送信
残り部分: a...（後ろの部分）     ← あなたのデバイスで確認

【プライバシー保護】
✅ サーバーはあなたのパスワード全体を知らない
✅ あなたのデバイスでのみ最終確認
✅ k-Anonymity プロトコルで安全
```

**学べること**:
- k-Anonymity は privacy-preserving protocol
- Have I Been Pwned でもあなたのパスワード全体を知らない
- プライバシーと安全性を両立できる

## 📖 各機能の詳細解説

### マスターパスワード

**何か?**: Vault 全体を保護する「マスターパスワード」

**強度判定**:
- ✅ 12文字以上
- ✅ 大文字・小文字・数字・記号を混在
- ✅ 一般的な辞書ワード（password など）を含まない
- ✅ 連続パターン（aaa など）を含まない

**安全性のメカニズム**:
```
あなたのパスワード
  ↓
PBKDF2-SHA256 (200,000反復)
  ↓
256-bit AES キー (ローカル生成)
  ↓
AES-256-GCM で Vault 全体を暗号化
  ↓
暗号化データを IndexedDB に保存
```

**なぜ安全?**:
- PBKDF2 反復により、ブルートフォース攻撃は不可能
- キーはあなたのデバイスでのみ生成
- サーバーは暗号化データのみ保有
- あなたがマスターパスワードを忘れたら、誰も復号化できない

---

### 生体認証（Touch ID / Face ID / Windows Hello）

**何か?**: パスワードの代わりに「指紋」「顔」で認証

**安全性のメカニズム**:
```
あなたの指紋 / 顔
  ↓
デバイスの安全エンクレイブ
（Apple Secure Enclave など）
  ↓
クレデンシャル ID 生成
  ↓
SHA-256 でキー導出
  ↓
Vault ロック解除
```

**なぜ安全?**:
- 生体認証データはデバイスから出ない
- サーバーはクレデンシャル ID のみを知る
- 指紋・顔データを盗聴不可
- 攻撃者は「物理的な指」「顔」が必要

---

### バックアップ（iCloud Drive / OneDrive / Google Drive）

**何か?**: Vault のバックアップを複数の場所に保存

**2層暗号化**:
```
平文 Vault データ
  ↓
[Layer 2] AES-256-GCM（マスターパスワード導出キー）
  ↓
[Layer 1] AES-256-GCM（デバイスキー = SHA-256(Device ID)）
  ↓
暗号化バックアップファイル
  ↓
iCloud Drive / OneDrive / Google Drive
  ↓
[Layer 3] クラウドプロバイダの TLS 暗号化
```

**なぜ2層必要?**:
- Layer 1（デバイスキー）: 別デバイスから復元時の追加認証
- Layer 2（マスターパスワード）: 最終的な復号化
- クラウドプロバイダが侵害されても読めない

---

### Have I Been Pwned（パスワード漏洩チェック）

**何か?**: 過去のデータ漏洩であなたのパスワードが公開されていないか確認

**k-Anonymity プロトコル**:
```
1. あなたのパスワード → SHA-1 ハッシュ → a4d87a...
2. 先頭5文字のみ送信: a4d87 ← サーバーに送信
3. サーバーが返すリスト: a4d87aa1, a4d87ab2, a4d87ac3, ...
4. あなたのデバイスが残り文字と照合: a... が一致？
5. 一致したら「漏洩データに含まれている」と判定
```

**なぜプライバシーが保護される?**:
- サーバーは SHA-1 の先頭5文字のみを受け取る
- 理論上、数百万の異なるパスワードが同じ先頭5文字
- サーバーはあなたの「本当のパスワード」を知らない
- あなたのデバイスでのみ最終確認

---

### RBAC（ロールベースアクセス制御）

**何か?**: 複数デバイス・家族ユーザーのアクセス権限管理

**4つのロール**:

| ロール | アクセス | 追加 | 編集 | 削除 | 共有 | デバイス管理 |
|--------|--------|------|------|------|------|------------|
| Owner | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| Editor | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ |
| Viewer | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| Guest | 共有リンク | ❌ | ❌ | ❌ | ❌ | ❌ |

## 🧪 実験・体験コンテンツ

### 実験1: PBKDF2 反復回数による時間差

```
反復数  | 計算時間 | ブルートフォース時間
--------|---------|-------------------
1,000   | 1ms     | ~1秒
10,000  | 10ms    | ~10秒
100,000 | 100ms   | ~100秒（~2分）
200,000 | 200ms   | ~200秒（~3分）
500,000 | 500ms   | ~500秒（~8分）
```

**学べること**: 反復回数を増やすと計算時間が線形に増加し、
ブルートフォース攻撃に要する時間も同様に増加する。

### 実験2: GCM タグの改変検知

```
【暗号文】
7a3c 4e9f a2b1 c5d8 ... (GCM タグ付き)

【1バイト改変】
7a3d 4e9f a2b1 c5d8 ... (先頭1バイト異なる)

【復号化試行】
❌ GCM タグが不正を検知 → 復号化失敗
```

**学べること**: GCM の認証タグは1バイトの改変も検知。
データ整合性が保証される。

### 実験3: パスワード強度と推定破り時間

```
【弱いパスワード】
"password123" (12文字、小文字+数字のみ)
強度: 40 / 100
推定破り時間: 約 10 秒

【強いパスワード】
"Tr0p1c@lSunset#2024" (20文字、大小英数+記号)
強度: 95 / 100
推定破り時間: 約 10,000 年
```

## ❓ よくある質問

### Q: マスターパスワードを忘れたらどうなる？

**A**: 復号化不可能です。デバイスからデータを抽出する方法もありません。
バックアップから復元することをお勧めします。

### Q: バックアップは安全？

**A**: はい。2層暗号化されているため、クラウドプロバイダが侵害されても読めません。

### Q: 生体認証は安全？

**A**: はい。指紋・顔データはデバイスから出ず、安全エンクレイブで保管されます。

### Q: パスワード強度の「10,000年」は本当？

**A**: はい。PBKDF2 の 200,000 反復 + 複雑なパスワードで、
最新の GPU でもブルートフォース攻撃は数千年かかります。
